# Публикация и шаринг (GitHub Pages)

## Что уже настроено

- `vite.config.ts` — `base: './'`, поэтому сборка работает и в корне домена, и в подпапке `/<repo>/`.
- `public/.nojekyll` — Pages не пытается обрабатывать файлы через Jekyll.
- `.github/workflows/deploy.yml` — на каждый пуш в `main` собирает проект (`typecheck → lint → test → build`) и публикует `dist`.

## Первая публикация

```powershell
git remote add origin https://github.com/<user>/<repo>.git
git add .
git commit -m "AiTripBuddy: даты, гант, шаринг и сравнение"
git push -u origin main
```

Затем в GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
После первого прогона workflow приложение будет доступно по адресу
`https://<user>.github.io/<repo>/`.

Локальная проверка production-сборки:

```powershell
npm run build
npm run preview
```

## Ссылки на наборы поездок

В библиотеке («Поездки») отметьте нужные поездки (или ничего — тогда берутся все) и нажмите **«Ссылка»**.
Формат:

```
https://<user>.github.io/<repo>/#trips=<код>
```

- Код — JSON с поездками, сжатый `deflate-raw` и закодированный в base64url (префикс `z`; без сжатия — `j`).
- При открытии ссылки набор импортируется в локальную библиотеку по `id`; более новые локальные версии не перетираются.
- Данные живут в хэше URL, поэтому ссылка не уходит на сервер и работает без бэкенда.
- Типичная длина: 1 поездка ≈ 350–600 символов, 3 поездки ≈ 1–2 КБ.

## Сравнение

В библиотеке выберите 2+ поездки → **«Сравнить»**. В окне сравнения:

- итог и цена на человека, цена дня катания;
- дни катания, ночи, число отелей и номеров;
- уровень отелей (★) и средняя цена за номер;
- питание и скипасс в день, время в дороге;
- использование бюджета и список курортов.

Все деньги приводятся к ₽ по внутреннему курсу (`src/lib/currency.ts`), чтобы валюты поездок не мешали сравнению.
