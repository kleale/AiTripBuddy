# AiTripBuddy — структура репозитория для агентов (харнесс)

Документ описывает, как агент (Kilo, Claude Code, Cursor, Codex) должен работать с репозиторием:
что читать первым, где границы, как проверять результат и что нельзя менять без обсуждения.

## 1. Порядок входа в контекст

| Шаг | Что читать | Зачем |
|---|---|---|
| 1 | `AGENTS.md` | команды, структура, инварианты, известные подводные камни |
| 2 | `docs/ARCHITECTURE.md` | слои, домен, API, кэш, LLM-слой |
| 3 | `docs/ROADMAP.md` | фазы, метрики, порядок задач |
| 4 | `tests/` | контракт поведения: что нельзя ломать |
| 5 | `public/roadmap.html` | визуальный статус майлстонов и беклог |

Правило: не начинать правки, пока не прочитаны `AGENTS.md` и релевантный тест.

## 2. Карта ответственности

```
src/types.ts          — домен. Меняется только вместе с normalizeTrip и тестами
src/data/             — справочники и контент. Источник правды, не дублировать
src/lib/              — чистые функции. Обязательно с тестом
src/stores/           — состояние и нормализация. Никакой вёрстки
src/components/       — UI. Логика расчётов живёт в lib, не в компонентах
src/styles/           — 11 модулей. main.css только импортирует
tests/                — спека. Новое поведение = новый тест
```

## 3. Жёсткие инварианты

1. **Числа считает код, не LLM.** `computeCosts`, `foodPerDay`, `buildSchedule`, `tripMetrics` — чистые функции. Модель может объяснять и парсить, но не выдавать цены.
2. **Один источник правды на слой.** Курс — `src/lib/currency.ts`; курорты — `src/data/resorts.ts`; связки — `src/data/resort-airports.ts`; гиды — `src/data/resort-guides.ts`.
3. **Внешние данные проходят через `normalizeTrip()`.** localStorage, библиотека, ссылка `#trips=`, пресет `#route=` — всё.
4. **Справочники связные.** Новый курорт обязан иметь аэропорт в `resort-airports.ts`, иначе `tests/data.test.ts` упадёт.
5. **Валюта поездки — единственная для сумм.** Конвертация только через `convertAmount()`.
6. **Публикация только через CI.** Пуш в `main` запускает workflow; не собирать и не выкладывать вручную.
7. **Секреты не попадают в код.** Ключи провайдеров — только на сервере, никогда в `src/`.

## 4. Гейт перед сдачей задачи

```powershell
npm run typecheck
npm run lint
npm test
```

Все три обязательны. Дополнительно для UI-изменений — прогон сценария в браузере (граф → отель → гид → карта).

Ожидаемое состояние: 123 теста зелёные, 0 ошибок ESLint, сборка без предупреждений о размере основного чанка.

## 5. Как добавлять контент

### Новый курорт

1. `src/data/resorts.ts` — `id`, название, страна, регион, координаты.
2. `src/data/resort-airports.ts` — минимум один аэропорт с `km` и `hours`; дальше 400 км — `hub()`.
3. `npm test` — валидаторы проверят аэропорт, дубли кодов и границы.
4. При наличии данных — гид в `src/data/resort-guides.ts` (части курорта, цены, координаты базы и вершины).

### Новый гид

1. Зоны с `base` и `summit` (реальные координаты), высотами, подъёмниками, километражем по сложности и ценой.
2. `passAll`, если есть единый скипасс.
3. Рекомендации: сезон, снег, кому подойдёт, 3–4 совета.
4. `tests/guides.test.ts` проверит высоты, валюты, уникальность зон и близость координат к курорту.

### Новый сезонный фильтр

`src/data/resort-season.ts` — таблица месяцев по странам; Хоккайдо выделен отдельно.

## 6. Границы, которые нельзя переходить без явного согласования

- Не добавлять платежи и бронирование: продукт остаётся советником, бронь — у провайдера по deeplink.
- Не вводить бэкенд и авторизацию без обсуждения: сейчас всё живёт в браузере и в хэше ссылки.
- Не менять формат `#trips=` и структуру `Trip` без миграции в `normalizeTrip()`.
- Не подключать тяжёлые библиотеки в основной чанк: карта и 3D грузятся лениво.

## 7. Известные подводные камни

| Симптом | Причина | Решение |
|---|---|---|
| `Worker failed to load` в проде | MapLibre ищет воркер рядом с чанком | `import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?url'` + `setWorkerUrl` |
| Предупреждение о двух источниках рельефа | hillshade и terrain на одном raster-dem | отдельные `dem` и `hillshadeDem` |
| MapLibre ломается в dev | пре-бандлинг Vite | `optimizeDeps.exclude: ['maplibre-gl']` |
| Белый экран после деплоя | абсолютные пути ассетов | `base: './'` |
| Пустой график после старых данных | нет `meals` / `rooms` | нормализация при загрузке |
| Курсы городов не кликаются | узлам выставлен `pointer-events: none` | `selectable: true` + `nodrag nowheel` |

## 8. Шаблон постановки задачи агенту

```
Задача: <что сделать>
Контекст: <файлы и текущее поведение>
Границы: <что не трогать>
Критерий готовности: <наблюдаемое поведение + тесты>

```

Агент обязан вернуть: что изменено (файлы и строки), результат гейта, что проверено в браузере, что осталось за границей задачи.

## 10. Метрики, которые агент не должен ухудшать

- Основной бандл ≤ ~130 КБ gzip (карта и 3D — отдельные чанки).
- Время до первого рендера графа — без регресса.
- 0 ошибок в консоли на сценарии «создать → заполнить → сохранить → открыть гид».
- 123 теста зелёные.
