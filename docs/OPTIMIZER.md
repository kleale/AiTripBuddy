# Мультикурортный оптимизатор (n4)

Версия v1: 2–4 курорта в интерфейсе, движок принимает до 8 для эвристики. Все суммы считаются существующими функциями приложения, а не LLM.

## Вход

`OptimizerInput` (`src/lib/optimizer.ts`):

- `resortIds` — 2–4 уникальных курорта из гида;
- `startDate`, `nights`, `minNights`, `pax`, `rooms`;
- `budget` — мягкое ограничение: превышение попадает в `warnings`;
- `profile` — `cheapest`, `balanced`, `premium`, `freeride`, `family`;
- `maxTransferHours` — предупреждение, если переезд длиннее;
- `maxVariants` — лимит перебора, по умолчанию 10 000.

`normalizeOptimizerInput()` приводит старые/битые данные к схеме v1: уникальные id, безопасные числа, дата, валюта и профиль.

## Этапы движка

1. `buildTransferMatrix()` считает каждую пару курортов один раз за запуск.
2. `orderCandidates()` делает полный перебор перестановок для 2–5 курортов; для 6–8 — nearest-neighbor от каждого старта и обратный порядок.
3. `allocations()` раскладывает ночи по курортам с минимумом `minNights`.
4. `buildVariant()` собирает `StayStop`/`RouteLink`, отель, скипасс и питание, затем вызывает `computeCosts()` и `buildSchedule()`.
5. `validateVariant()` проверяет сумму ночей, монотонность дат, календарь и даты мероприятий.
6. `scoreAll()` нормирует цену, время, дни катания, комфорт и сезон по весам профиля.
7. `dominates()` оставляет Pareto-фронт; `pickDistinct()` выбирает до 4 представителей.
8. `OptimizerModal` применяет вариант через `normalizeTrip()` и хранит снимок предыдущей поездки для отката.

## Ограничения v1

- Переезды — оценка по расстоянию и виду транспорта, без расписаний и реальных офферов.
- Нет Web Worker: 4 курорта укладываются в perf-бюджет, лимит вариантов защищает от зависания.
- Бюджет и максимальный переезд — предупреждения, не жёсткие фильтры.
- Совместное редактирование вариантов и сохранение набора вариантов не входят в v1.
- Карта — схематичная SVG-линия по координатам курортов, не маршрут по дорогам.

## Метрики

`src/lib/optimizer-metrics.ts` хранит локально: запуски, число вариантов, применения, суммарную экономию к прежней смете, время последнего расчёта. Метрики видны в админке и футере окна.
