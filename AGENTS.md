# AiTripBuddy

MVP-конструктор горнолыжной поездки: маршрут на графе, отели, скипасс, питание и смета.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Vite dev-сервер на `http://localhost:5173` |
| `npm run build` | `vue-tsc --noEmit` + production-сборка |
| `npm run typecheck` | проверка типов без сборки |
| `npm run lint` | ESLint (flat config, TS + Vue) |
| `npm test` | Vitest, юнит-тесты в `tests/` |
| `npm run test:watch` | Vitest в watch-режиме |

Перед завершением задачи запускайте `npm run typecheck && npm run lint && npm test`.

## Структура

- `src/types.ts` — доменные типы (`Trip`, `Stop`, `RouteLink`, `Meals`).
- `src/data/` — справочники: города/аэропорты, курорты, связки «курорт ↔ аэропорт», цены питания.
- `src/lib/` — чистые функции: `costs`, `currency`, `geo`, `format`, `schedule` (гант), `compare` (метрики), `share` (ссылки).
- `src/stores/` — реактивные сторы: текущая поездка, библиотека сохранённых, импорт из ссылки.
- `src/components/` — граф, гант, карта, смета, модалки (поездки, сравнение), узлы маршрута.
- `src/styles/` — `main.css` только импортирует модули (`base`, `layout`, `timeline`, …).
- `tests/` — Vitest: стоимость, геометрия/валюты, расписание, сравнение, шаринг, справочники.
- `docs/DEPLOY.md` — GitHub Pages, формат ссылок, сравнение.
- `docs/AGENTS-HARNESS.md` — как агенту работать в репозитории: порядок чтения, инварианты, гейт, границы.
- `public/roadmap.html` — интерактивный роадмап на два продукта: вкладки AiTripBuddy и SnowMap Pro, узлы майлстонов с раскрытием, чек-листы и беклоги с сохранением галочек. У SnowMap Pro зафиксирован стек: React Native + React Native Web на общем TypeScript-монорепо.
- `.github/workflows/deploy.yml` — CI: typecheck → lint → test → build → Pages.

## Правила

- Все денежные суммы хранятся в валюте поездки; курс — `src/lib/currency.ts`, единственный источник правды.
- Числа считает код, не LLM: `computeCosts`, `foodPerDay`, `buildSchedule`, `tripMetrics` — чистые функции с тестами.
- Любые внешние данные нормализуются через `normalizeTrip()` перед использованием (localStorage, библиотека, ссылка).
- Даты отелей — `checkIn` (`YYYY-MM-DD`), у участков — `date`/`time`. Гант строит строки и для отелей, и для событий перелёта/трансфера; без дат дни нумеруются условно.
- Каскад дат идёт только вперёд: правка заезда/ночей или даты участка сдвигает следующие отели и участки; текущая точка, предыдущие точки и входящий участок остаются на месте (`cascadeAfterStop`/`cascadeAfterLink`).
- Узел отеля переключается между «Курорт» и «Город» (`placeKind`), чтобы вернуться с курорта в город перед вылетом.
- Справочники связные: `tests/data.test.ts` проверяет, что у каждого курорта есть существующий аэропорт и нет дублей кодов.
- Ссылки на наборы — `#trips=<code>` (`src/lib/share.ts`), данные только в хэше, без бэкенда.
- Кнопки отелей — `src/lib/hotel-links.ts`: Booking, Trip.com, Ozon и Яндекс получают место, даты, гостей, число номеров и валюту; без дат ведут на обычный поиск. Название отеля необязательно: если место в узле не выбрано, берётся город ближайшего аэропорта прилёта.
- Цена за номер привязана к сайту: у `StayStop` поля `hotelSource` и `hotelPriceAt`, их нормализует `normalizeTrip`, а селект «Где бронирую» в `StayNode` фиксирует дату.
- Маршрут линейный: `links[i]` соединяет `stops[i]` и `stops[i+1]`. Соединять мышью можно только соседние узлы; для свободных связей нужна модель с явными `from`/`to`.
- Вставка точки (`insertStayAfter`) добавляет отель и участок, сохраняя старый участок; удаление (`removeStop`) объединяет соседние участки и не трогает следующие узлы.
- Вид транспорта — `src/lib/transport.ts`: самолёт, поезд, автобус, такси, автомобиль, паром; цвет и штрих ребра берутся оттуда же, что и в легенде.
- Шапка на телефоне: до 760 px кнопки и ссылки уходят в `.header-menu`, открывается бургером; на десктопе `display: contents` оставляет их в строке.
- Линейный маршрут с необязательной нодой подготовки: `Trip.prep` не входит в `stops`/`links`, рисуется отдельной нодой слева и не влияет на см�мету.
- Подготовка: `src/data/gear.ts` (чек-лист 60 пунктов, бренды по бюджетам, бюджет РФ), `src/data/board-info.ts` (прогибы, парафин, сервис, одежда), `src/data/pro-athletes.ts` (20 ориентировочных профилей райдеров), `src/lib/gear-fit.ts` (размеры, жёсткость, стиль, стойка), `src/lib/prep.ts` (default/normalize), `PrepNode`, `PrepModal`, `DisciplineSlider`, `StyleSlider`, `GearFitDiagram`, `StanceDiagram`.
- Фрирайд в подготовке: пока не подтверждён лавинный набор (или не отмечены бипер/щуп/лопата), советы по фрирайду скрыты.
- Стиль карвинг/фристайл/фрирайд/флэт — второй слайдер, влияет на длину, ширину и жёсткость; стойка хранится в prep.stance (углы, сдвиг, свитч, наклон хайбека).
- Чек-лист открывается первым; группа «Доп. снаряжение» стоит в правой колонке и помечена excludeFromProgress, поэтому не входит в шкалу «Собрано».
- Вкладка «Доска» разбита на подвкладки: прогибы (9 вариантов), формы, стойка, материалы, настройка, уход, подбор. Ширина сноуборда считается от размера ботинка и стиля, карвинг добавляет ширину.
- `prep` нормализуется `normalizeTrip`, сохраняется в localStorage и ссылке; старые поездки остаются без подготовки.
- Записи в localStorage дебаунсятся (400 мс) и сбрасываются на `beforeunload`/`pagehide`.
- Leaflet подгружается лениво (`defineAsyncComponent`), чтобы не раздувать основной бандл.
- Сборка переносимая (`base: './'`), публикуется на GitHub Pages workflow-ом.
## Гид по курорту и 3D-карта

- `src/data/resort-guides.ts` — рекомендации, части курорта (цены скипасса, трассы по сложности, подъёмники) и реальные координаты базы/вершины. Гиды: Нисеко, Хакуба, Красная Поляна, Роза Хутор, Гудаури, Местиа, Шерегеш, Красное Озеро, Туутари Парк, Майрхофен, Кировск (Хибины), Домбай, Приэльбрусье, Манжерок, Архыз. Валюты гидов: RUB, EUR, GEL, JPY.
- `src/components/ResortCatalog.vue` — каталог всех курортов: поиск по названию/региону/стране, фильтры по стране и месяцу сезона, «только с гидом», кнопка «Посмотреть гид».
- `src/data/resort-season.ts` — ориентировочные месяцы катания по странам (Хоккайдо выделен).
- `src/components/ResortGuideModal.vue` — большое окно гида: слева 3D-карта, справа рекомендации, скипассы по частям, сложность и советы.
- `src/components/ResortScene3D.vue` — MapLibre GL с 3D-рельефом, переключателем 3D/сверху и линейкой расстояний: OSM-тайлы + raster-dem (Terrarium), наклон 62°, трассы цветом по сложности, подъёмники пунктиром, нумерованные пины частей курорта.
- Требуется WebGL; при его отсутствии показывается заглушка. Тайлы и DEM грузятся из сети, поэтому гид не работает полностью офлайн.
- `WeatherPanel` во вкладке «Снег» (доступна у всех гидов): `altitudePoints()` даёт базу, середину и вершину, `forecastUrl(point, elevation)` передаёт высоту в Open-Meteo, `weekDays()` — первые 7 дней. В кнопках высот справа виден снег в см. Неделя — сетка из 7 колонок, чтобы не переносилась на вторую строку.
- В 3D-карте переключатель вида — `3D / 2D / Линейка`; слои трасс, подъёмников и парков стоят справа под переключателем, а не над названиями частей курорта.
- Справочник городов (`src/data/cities.ts`) — 239 аэропортов, включая крупные города Японии и России; Фудзикавагутико привязан к Сидзуоке (FSZ), Киото — к Кансаю (UKY).
- MapLibre подключён лениво (отдельный чанк ~300 КБ gzip) и исключён из `optimizeDeps` в `vite.config.ts`, иначе ломается worker в dev.

## Известные подводные камни

- MapLibre worker: сборка ищет `maplibre-gl-worker.mjs` рядом с чанком и падает с «Worker failed to load». Поэтому в `ResortScene3D.vue` воркер подключается явно: `import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?url'` + `setWorkerUrl(workerUrl)`.
- Для 3D-рельефа и hillshade нужны разные raster-dem источники (`dem` и `hillshadeDem`), иначе MapLibre ругается и качество падает.
- `optimizeDeps.exclude: ['maplibre-gl']` обязателен: иначе Vite ломает worker в dev.
- Trip.com принимает поиск по `cityName` + `searchWord` без числового city id — проверено ссылкой с датами.
- Ozon Travel отдаёт 403/таймаут ботам, а его `search-new` понимает даты и гостей; место передаётся текстом и может не распознаться — не выдавать это за гарантированную выдачу города.
- Нода подготовки не входит в `stops`, поэтому `fitView` после её появления вызывается с задержкой (180/600 мс): иначе VueFlow измеряет узел до отрисовки и кадрирует только маршрут. У неё `selectable: true`: при `false` VueFlow ставит inline `pointer-events: none`, и кнопка «Открыть подготовку» не кликается. На телефоне `fitView` получает только id остановок, иначе нода подготовки выталкивает маршрут за экран.
