Репозиторий как контракт: правила, тесты и границы вместо устных договорённостей

AiTripBuddy/
├── AGENTS.md            # правила, команды, инварианты, грабли

│   ├── ROADMAP.md       # фазы и метрики (текстовая версия)
│   ├── ARCHITECTURE.md  # слои, домен, API, кэш, LLM
│   ├── DEPLOY.md        # Pages, формат ссылок, сравнение
│   └── AGENTS-HARNESS.md# как агенту работать в репо
├── src/
│   ├── types.ts         # домен: Trip, Stop, RouteLink, Meals
│   ├── data/            # справочники и контент
│   ├── lib/             # чистые функции, покрыты тестами
│   ├── stores/          # состояние и нормализация
│   ├── components/      # UI: граф, карты, модалки, узлы
│   └── styles/          # 11 модулей, main.css только импортирует
├── tests/               # 123 теста = контракт поведения
├── .github/workflows/    # typecheck → lint → test → build → Pages
└── public/              # .nojekyll, этот роадмап

Агент читает AGENTS.md первым: там команды, структура, инварианты («числа считает код, не LLM») и известные подводные камни (воркер MapLibre, два DEM-источника, optimizeDeps).

1Один источник правды на слой. Курс — lib/currency.ts, курорты — data/resorts.ts, нормализация — normalizeTrip(). Дублировать данные запрещено.
2Тесты — это спека. Перед изменением поведения смотри tests/; новая функция приходит с тестом. 123 теста должны остаться зелёными.
3Гейт перед сдачей: npm run typecheck && npm run lint && npm test. Красный гейт = задача не сделана.
4Деньги только числами. LLM объясняет и парсит, но не генерирует цифры. Любая цена — из справочника с пометкой источника.
5Внешние данные нормализуются. localStorage, ссылка, пресет — всё проходит через normalizeTrip(), иначе старые данные роняют UI.
6Справочники связные. Новый курорт без аэропорта или с дублем кода ломает tests/data.test.ts — это защита от полупустых данных.
7Деплой не ручной. Пуш в main запускает workflow; агент не публикует в обход CI.
8Документируй грабли. Каждая неочевидная поломка (воркер, DEM, base path) попадает в AGENTS.md, чтобы не повторяться.

Монетизация и метрики

Платить за уникальное, а не за базовую карту

Модель

1Freemium. Базовые карты и трекинг бесплатно; офлайн-карты, продвинутая аналитика и АИ сверх лимита — подписка.
2Партнёрские комиссии. Отели, прокат, школы инструкторов, туры и кемпы, спа.
3Реклама курортов — аккуратно, не в ущерб UX.
4Premium для бизнеса. Курорты платят за продвижение и аналитику загруженности.

Метрики

1Активные пользователи на курорт — критическая масса для краудсорсинга.
2Удержание зимой и летом (проверка сезонной гипотезы).
3Конверсия в Premium и доля платящих.
4Завершённые поездки через приложение и партнёрские брони.
5Точность данных: верификация ширины и уклона, качество треков.

Архитектура и харнесс

Общее ядро, разные слои данных по активностям

snowmap-pro/              # монорепо, общий TypeScript на всё
├── apps/
│   ├── mobile/       # React Native (iOS + Android), Expo
│   ├── web/          # React Native Web (планирование поездок)
│   └── api/          # Node + TS: граф, маршруты, соцфичи
├── packages/
│   ├── core/         # граф, оптимизация, профиль — без платформы
│   ├── ui/           # RN-компоненты, общие для mobile и web
│   ├── map/          # maplibre-react-native + maplibre-gl (web)
│   ├── activity-snow/ # трассы, подъёмники, скипасс
│   ├── activity-mtb/  # трейлы, байк-парки, шаттлы
│   ├── activity-trail/# тропы, приюты, вода
│   ├── health/       # Apple Health, Health Connect, Garmin
│   ├── offline/      # SQLite, очередь синхронизации, тайлы
│   ├── ai/           # function calling, кэш, роутинг моделей
│   └── shared/       # схемы Zod, типы, форматтеры
├── services/
│   ├── ingest/       # OSM, OpenSkiMap, DEM, погода, краудсорсинг
│   └── telemetry/    # треки → уточнение карт и загруженности
└── tests/             # граф, оптимизация, данные, форматтеры

Ядро не знает про активность: узлы и рёбра с атрибутами. Сноуборд, MTB и трейлы — это наборы правил и UI-слоёв поверх одного движка маршрутов и одного профиля нагрузки.

1Данные с провенансом. У трассы и цены — источник, дата и уровень доверия (verified / curated / estimate).
2Числа считает код. Уклон, вертикаль, нагрузка, бюджет — чистые функции с тестами; LLM только объясняет.
3Офлайн — не режим, а требование. Карты, профиль и план доступны без сети; синхронизация при возврате.
4Безопасность вне ответственности. Медсоветы и лавинные решения — только ссылки на официальные источники.
5Один справочник курортов переиспользуется с AiTripBuddy: не дублировать координаты и сезонные окна.
6Гейт как в AiTripBuddy: typecheck, lint, тесты, сборка. Краудсорсинг-данные проходят модерацию до публикации.
